# SoudaCore ERP — API Documentation

A structured reference for the real `soudacore-api` JSON API — every
endpoint lives under a single `/api/v1` prefix (354 routes, confirmed
directly against `routes/api.php`, not estimated). This is a real
reference, generated by inspecting the actual route file and
controllers, not a template. **A full machine-readable OpenAPI spec
does not exist yet** — this document is the honest current substitute;
see the note at the end for why that's still open.

## Base URL & versioning

```
https://<your-domain>/api/v1
```

Every route in this application lives under this one prefix —
confirmed directly (`grep` count of `Route::prefix('v1')` wrapping the
entire route file: exactly one). There is no `v2` yet; a future
breaking change would get its own `/api/v2` prefix alongside this one,
not a replacement of it.

## Authentication

Bearer token via Laravel Sanctum. Two separate identity types, each
with their own login endpoint and their own token:

- **Tenant users**: `POST /api/v1/auth/login` → `{ access_token,
  refresh_token, ... }`. Send `Authorization: Bearer <access_token>`
  on every subsequent request, plus `X-Tenant-ID: <tenant-id>` (or
  resolve the tenant from your subdomain in production — see
  `config/tenancy.php`).
- **Super Admin** (platform-level, separate from any tenant):
  `POST /api/v1/admin/auth/login` — same bearer-token pattern, scoped
  to `/api/v1/admin/*` routes only.

Access tokens expire (`SANCTUM_ACCESS_TOKEN_TTL_MINUTES` in
`.env.example`, default 60 minutes) — use
`POST /api/v1/auth/refresh` with your refresh token to get a new one
without re-authenticating. Refresh tokens rotate on use and carry real
theft detection (see `docs/FOUNDATION.md`).

Sensitive auth endpoints (`login`, `otp/verify`, `refresh`,
`forgot-password`, `reset-password`, tenant registration, Super Admin
login) carry a real, tighter rate limit — 10 requests/minute, keyed by
IP and the submitted identifier together (see
`docs/PRODUCTION_READINESS.md`). Every other endpoint uses the
standard 60/minute API-wide limit.

## Response envelope

Every successful response:

```json
{ "data": { ... } }
```

or, for a paginated list:

```json
{
  "data": [ ... ],
  "links": { "first": "...", "last": "...", "prev": null, "next": "..." },
  "meta": { "current_page": 1, "last_page": 5, "per_page": 15, "total": 68 }
}
```

## Error format

Every error, regardless of cause, follows the same shape — and never
leaks a stack trace or raw exception message when `APP_DEBUG=false`
(verified — see `bootstrap/app.php`'s exception handler):

```json
{
  "message": "The given data was invalid.",
  "errors": { "email": ["The email field is required."] }
}
```

| Status | Meaning |
|---|---|
| 401 | Not authenticated, or token expired/invalid |
| 403 | Authenticated, but missing the required `permission:module.action` grant |
| 404 | Resource not found (or belongs to another tenant — RLS makes it invisible, not just forbidden) |
| 422 | Validation failed (Form Request rejected the payload) |
| 429 | Rate limited |
| 503 | `GET /api/v1/health` reporting a real dependency (database/cache/queue) as unavailable |

## Filtering, sorting, pagination

Built on `spatie/laravel-query-builder` — every list endpoint supports
real, consistent query parameters (not every field on every model;
each repository's `$allowedFilters`/`$allowedSorts` arrays are the
real source of truth for what a given endpoint accepts):

```
GET /api/v1/crm/leads?filter[status]=open&sort=-created_at&page=2&page_size=25
```

## Multi-tenancy

Every tenant-scoped endpoint is automatically filtered to the
authenticated user's own tenant by PostgreSQL Row-Level Security —
not just application-layer scoping. Attempting to access another
tenant's resource by ID returns 404, not 403 — it's genuinely invisible
at the database layer, not just blocked at the application layer (see
`docs/DATABASE_VERIFICATION.md`).

## Health check

```
GET /api/v1/health
```

Public, no auth required. Real dependency checks (database, cache,
queue) — see `docs/PRODUCTION_READINESS.md`. Returns 200 when healthy,
503 when any component is down.

## What's not covered here

**A generated, machine-readable OpenAPI/Swagger spec does not exist.**
Generating one accurately for 354 real endpoints — correct request/
response schemas per endpoint, not a best-effort approximation — is a
substantial task in its own right and remains open in
`docs/ROADMAP.md`'s Backlog, named there explicitly rather than
silently skipped. This document is the honest, real substitute until
that exists: accurate at the level of routes, auth, conventions, and
module map, but not a per-field schema reference. For exact request/
response shapes today, the real source of truth is each module's own
Form Request classes (`app/Http/Requests/`) and API Resource classes
(`app/Http/Resources/`) — both are real, readable PHP, not generated
from anything else.
